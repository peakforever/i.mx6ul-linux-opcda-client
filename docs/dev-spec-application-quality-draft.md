# 应用品质编码约定草案（2026-11-12，待确认）

> 已废弃。用户随后确认兼容方案：低 8 位保留 OPC 标准品质，高 8 位为应用原因。以 [正式约定 v1](application-quality-format.md) 为准，下文仅保留设计讨论记录，不实施。

## 状态与范围

用户提出：不透传 OPC Server 品质，应用使用约定扩展品质，表达网络、认证、超时等故障。本文件为可审核的契约草案，尚未替换当前实现；编码确认后补齐开发门禁规格、修改代码及接收端说明。

当前 30 字节布局仍可容纳新的 uint16 品质，但字段语义会变化。发送端和接收端必须协同采用新约定，不能继续用 OPC Good/Bad 位掩码解析，也不能靠字段值自动区分所有历史厂商品质。

## 建议编码

`quality = (valueState << 8) | reason`，按原协议小端编码。

| 高 8 位 valueState | 定义 |
|---|---|
| `0x00` | 初始值：本进程尚未取得可编码样本，数值为默认 0、采样时间 0 |
| `0x01` | 当前样本：来自最近有效读取，未超过新鲜度期限；不代表源品质必然正常 |
| `0x02` | 保持值：本轮失败/缺失、读过期或连接故障，保留最后可编码值及原采样时间 |
| 其余 | 保留，接收端按未知状态处理，不能认作正常 |

| 低 8 位 reason | 定义与证据要求 |
|---|---|
| `0x00` | 正常采集，仅用于当前样本且源品质正常 |
| `0x01` | 等待首次数据；尚无已知失败原因 |
| `0x10` | 主机名解析失败 |
| `0x11` | 网络/主机不可达：明确的不可达异常；不由超时推断 |
| `0x12` | TCP 连接失败：连接拒绝或其他建立连接失败，未细分 |
| `0x13` | 连接或请求超时：只能证明等待超时，不声称一定是防火墙或密码 |
| `0x20` | 明确认证失败：仅在返回明确登录/认证失败证据时使用；不区分用户名错、密码错或其他认证拒绝 |
| `0x21` | 访问拒绝，认证/授权未细分：例如 DCOM `0x80070005`，不能直接标为密码错误 |
| `0x22` | 目标 OPC 组件未注册 |
| `0x23` | RPC 服务/端点不可用 |
| `0x24` | RPC 调用/连接中断 |
| `0x25` | 服务忙或资源不足，需明确相应错误 |
| `0x26` | 协议/兼容性错误，未推断具体损坏原因 |
| `0x30` | 本轮点位缺失；没有独立错误证据时使用 |
| `0x31` | 点位读取失败；不凭通用读失败推断 ItemID 不存在 |
| `0x32` | 样本不能编码：类型、转换或采样时间范围异常 |
| `0x33` | 读过期：尚无新错误，但连续达到三个周期无完整读取提交 |
| `0x40` | 源数据品质异常：服务器 Bad 映射为应用原因，不透传原始码 |
| `0x41` | 源数据不确定：服务器 Uncertain 映射为应用原因 |
| `0x42` | 源品质未知或缺失，不能按正常值处理 |
| `0xFF` | 其他/未归类故障，详细原因留在脱敏日志 |

来源品质仍可用于判断数据是否可用，但 UDP 中只发送本约定。源 Bad/Uncertain 样本仍可更新数值和采样时间，其状态为当前样本、原因分别为 `0x40/0x41`。这不是正常采集；接收端只有 `0x0100` 才按正常有效样本处理。原始源品质和原始错误码不挤入这 16 位，必要时保留在诊断中。

## 示例

| 场景 | 品质 | 值与时间 |
|---|---|---|
| 刚启动等待 | `0x0001` | 0，时间 0 |
| 尚无值且网络明确不可达 | `0x0011` | 0，时间 0 |
| 尚无值且 DCOM 拒绝 | `0x0021` | 0，时间 0 |
| 正常取得当前样本 | `0x0100` | 新值，原始采样时间 |
| 当前样本源品质 Bad | `0x0140` | 新值，原始采样时间 |
| 已有值后明确不可达 | `0x0211` | 保持最后值，时间不刷新 |
| 已有值后明确认证失败 | `0x0220` | 保持最后值，时间不刷新 |
| 已有值后访问拒绝 | `0x0221` | 保持最后值，时间不刷新 |
| 已有值后超时 | `0x0213` | 保持最后值，时间不刷新 |
| 无回调且达到过期阈值 | `0x0233` | 保持最后值，时间不刷新 |

## 状态选择与恢复

- 连接级已知故障影响全部点，原因优先于点位缺失和无新数据推断；状态仍按各点是否曾有可编码样本区分初始/保持。
- 重试等待不覆盖最后已知故障为笼统“重连中”；重连进度由日志表达。后续失败有新证据时更新原因。
- 连接恢复/绑定成功本身不把点设为正常；各点取得新的当前样本后才恢复对应应用品质。点的失败原因在新轮缺失时不能误报成正常。
- 源 Bad/Uncertain 与“读取失败”不同：前者是当前样本，后者保持缓存。保持时主原因表达当前导致保持的故障，不声称能在一个字段表达全部历史异常。
- 发送计数、UDP 心跳和重连等待都不能更新 OPC 采样时间或解除数据过期。UDP 发送/接收故障由发送统计和接收端超时表达，不能假设发送失败的包还能携带故障码到达。
- 当前完整配置错误（JSON 不存在/格式错误）可能发生在点表构建前，不能承诺向未知点表发送“配置错误品质”；仍通过启动错误和服务状态报告。
