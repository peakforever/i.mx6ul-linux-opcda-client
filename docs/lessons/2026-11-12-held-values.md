# 保持值发送：不能让网络恢复阻断输出

用户变更：缺失点不再跳过，初始 0，失败时发送最后值及应用 Bad 品质。

必须同时检查：

- 若只在读结束补值，整次 RPC 卡住/首次连接/同步重连退避时仍会停发。发送必须独立调度，测试须阻塞真实的 fake RPC 而不是只手动调用发送函数。
- 发送保持值不能更新时间戳、恢复 Good 或更新连接看门狗，否则会掩盖数据过期和断线。
- 非数值/转换失败不能覆盖最后可编码值；Bad 数值与读失败不同，前者保留服务器 OPC 低字节品质，高字节由应用接管。
- 初始值 0 不代表有效零值；品质为等待初始数据，时间为 0。重启不继承上次进程缓存。
- 回调线程和发送线程并发，缓存需复制并在完整读结束原子提交；旧连接回调失效要求不能回退。
- 文档、旧测试中“全空轮不发/缺失跳过”必须同步替换。协议布局不变不等于运行语义没变。
- 高字节原因必须沿首次失败、每次重试、逐点读失败和旧连接身份过滤传播；不能只在最终退出异常中识别。公共 RPC 失败的 finally 轮次结束不能抹掉连接原因，看门狗推断也不能覆盖先前实际错误。
- 不能依异常消息“密码错”或 `0x80070005` 猜认证失败。对照微软定义审计历史映射，避免将 RPC 1727 当端点未找到、1747 当服务忙。

规格及验收见 [保持值规格](../dev-spec-held-values.md)。
