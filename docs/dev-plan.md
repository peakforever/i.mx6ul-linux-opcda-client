## 迭代 2:多 Item 采集 + OPC2ECU UDP 发送(设计已定案)

目标:实现原 Windows 程序的替代品——多 Item 周期采集、30 字节小端记录、
48 条/报文组包、UDP 发送到网关 OPC-DA 驱动(端口 5353)+ V1.2 心跳在线探测。

状态:2026-08-20 设计收敛(协议文档 v1.2 到位 + 与用户讨论定案),规格见
docs/dev-spec-iter2.md,待 Codex 开工。

定案摘要:
- 数据模型:周期快照(协议 5.1.1 确认,离线期间业务照发)
- 配置格式:points.json(JSON 点位表;连接参数仍走 opc.properties)
- 组包:每周期全量,≤48 块/包拆包,单向无应答不重传
- 心跳:1000ms/500ms 超时/连续 3 次离线,会话 ID 自增匹配,独立调度
- MD5 字符集:md5Charset 配置项(默认 US-ASCII,支持 GBK,集成对照确认)
- 目标地址:udp.host 配置化,默认 127.0.0.1(客户端与驱动同机)
- 契约文档:docs/OPC-DA驱动自定义UDP通讯协议v1.2.docx(同事,V1.2 兼容 V1.1)

遗留外部依赖:

## 集成架构定案(2026-08-20)

背景:原架构中 OPC 采集由部署在 OPC server 主机上的 Windows 应用 opc2ecu
完成,经以太网 UDP 把 30 字节记录发到 ECU 网关;ECU 内 C++ 应用的驱动数据
走全局变量(紧耦合),无法直接挂接新驱动。

定案:OPC DA client(本 Java 工程)作为网关上的独立进程,以 OPC2ECU UDP
协议与 ECU C++ 应用通信——协议边界、记录格式、组包规则与 Windows 版
opc2ecu 完全一致,发送目标为本机回环(127.0.0.1 + ECU 应用 UDP 端口)。
ECU C++ 应用零改动。

含义:
- 数据面:UDP 报文(30B 记录 × ≤48/报文),与 C++ 应用既有接收逻辑无缝衔接
- 控制面/配置面:点位表、启停、状态上报走后续定的机制(平台/工作台),不占
  用 UDP 数据面
- 写操作:2026-08-20 客户确认不要求,所有迭代均不做(需求变更除外)
- 与工作台(Go)的关系:工作台是测试工具,本工程是生产驱动;两者都可能在
  网关共存,资源预算按 256MB 统筹

## 贯穿性工程要求

- Java 8 字节码目标(网关 Zulu JRE 8 compact1),Maven 构建,单元测试随代码
- 256MB RAM 约束:JVM -Xms16m/-Xmx48m 起步,新增功能保持内存敏感
- 安全:密码只走环境变量/密钥文件,配置不入库,日志不打印凭据
- 每个迭代结束:实机验收(网关↔Windows+Matrikon)+ 资源实测记录
- 提交规范:英文 summary,功能/测试/文档分 commit
