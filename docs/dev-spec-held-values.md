# 保持最后点值与持续品质发送规格（2026-11-12）

> 后续用户确认扩展品质：[正式品质约定](application-quality-format.md)。下文 `0x20/0x14` 是合成品质的低字节；高字节增加应用原因。成功样本保留 OPC 低 8 位，不再透传厂商高字节；具体原因以正式约定为准。

## 一、功能概述

用户确认实施“应用降品质、持续发送最后点值，初始默认 0”。替代 [旧单点隔离规格](dev-spec-point-isolation.md) 的缺失点跳过、不补旧值语义；单点隔离、ItemID 原文和旧连接回调失效要求继续生效。目标为 Java 8 / i.MX6UL，UDP 记录布局不变，不增加配置字段。

按开发门禁规格模板及缺陷案例 `iot-gateway-planning/docs/lessons/2026-08-21-ping-count-timeout.md` 检查时序和真实路径；本轮不沿用此前跳过审核的决定，Hermes、用户审核及合入仍待用户流程。

## 二、接口定义与输入

- 入口：`--collect points.json`；预检、枚举和单点探测不改变。
- `items`、`periodMillis` 使用现有校验；周期为正 int 毫秒（1～2147483647），无新增默认值，建议 ≥500 ms；items 非空、原文唯一。
- 每个配置点进程内初始化为 double `0`、品质 `0x0120`（高字节等待数据，低字节 Bad/Waiting for Initial Data）、采样时间 `0`（未知）。初始值固定，不持久化，不新增逐点配置。
- 读到可编码值（含布尔 0/1）及可编码时间时，保存值、服务器 OPC 低 8 位品质、原始采样时间。Bad/Uncertain 数值同样保存；“最后值”不是“最后 Good 值”。空时间仍按既有协议编码为 0。
- 缺失、读取错误、转换异常、非数值、时间不在 uint32 秒范围：不覆盖缓存；已有值的品质低字节为 `0x14`（Bad/Last Known Value），从未成功取得可编码值的点为 `0x20`；高字节为对应应用原因。
- 成功样本的低字节逐位保留，高字节归零；应用生成 Bad 时不继承服务器厂商位或限值位。完整编码表见正式品质约定。
- 每轮发送全配置点，顺序不变，每包最多 48 条，每条仍 30 字节。保持值不伪造新采样时间。

## 三、参数与时序约束

- 独立单线程周期发送，首次立即发送初始化状态；后续采用固定延迟：下一轮开始 ≥ 上轮结束 + P，不积压补发错过的 tick，不承诺硬实时。
- OPC 回调只提交完整读取轮次的缓存更新；新轮开始清掉未提交的旧轮，不能把不同轮次拼成新样本。
- 轮次结束后，该轮缺失/不可编码点立即标为保持 Bad；显式连接故障立即清除所有点的新鲜状态。
- 尚未显式报错但 RPC 挂起时，以单调时钟检测新鲜度：`age >= 3 × P` 降为保持 Bad；最迟下一次发送观察到，正常发送不构成成功读取，也不喂活连接看门狗。
- `3 × P` 使用 long 并饱和保护。网络调用/退避可远大于 P，不能放到发送线程；首次连接、绑定、重连期间都持续发送。
- 配置关闭重连或耗尽有限重试次数时沿用退出语义；服务退出后不承诺继续发送。进程终止/ECU 断电仍由接收端收包超时判断。

## 四、依赖默认值审查

| 依赖 | 默认与风险 | 本次处理 |
|---|---|---|
| Utgard 同步读取 | 网络读阻塞、第三方 RPC 不一定响应中断 | 发送独立线程，不等待连接锁 |
| 重连管理 | 原 start 首次失败退出；重连同步退避 | 采集专用 startWithRecovery，首次失败也按已配置策略重试；原 API 不变 |
| 定时器 | 周期任务未捕获异常会停调度；固定频率可能追赶 | 固定延迟、异常日志、独立关闭 |
| OPC 品质 | 低字节 `0x20` 等待初值、`0x14` 最后值；类别均 Bad | 高字节应用原因，成功样本保留服务器低字节 |
| UDP | send 成功不等于到达；网络 send 不承诺无限阻塞可取消 | 保留发送计数和错误处理，现场验证接收和停止时限 |
| 时钟 | 系统时间可能校准 | 新鲜度用单调时钟，采样时间保留服务器时间 |

品质依据：[OPC Foundation 发布的定义](https://github.com/OPCF-Members/UA-.NET-Legacy/blob/master/SampleApplications/Include/opcaedef.h)。

## 六、测试计划

以可注入时钟覆盖 P=1/default/max 的超时边界；真实定时任务以 latch 观察阻塞首连及重连期间多轮发包；保持缓存独立于未完成轮次；迟到旧连接不能改变值或品质。故障路径通过不等于现场功能通过。包内值、品质和时间须一起断言，而不是只计数。

## 七、横切属性

- 缓存和每轮临时快照为 O(N)，无无界队列、不存历史序列；额外一个发送线程，读取失败不创建额外线程。
- 启停关闭发送任务，再关闭连接和心跳；在途第三方 RPC 退出仍有既有限制，现场计时。
- 缓存复制数值及 Calendar，外部可变对象不能修改已保持样本；不可编码样本计数，不记录值或密码。
- 摘要区分最近读取点数与当前保持 Bad 点数；发包不能被解释为 OPC 健康。
