## 今日闭环:Kepware 采集"有心跳无数据"根因修复

### 现象
- 用户报:新 Kepware 机器(192.168.3.230)上,opc2ecu 有心跳(4B 包),但无业务数据(30B 包)
- 昨天待办"Kepware DCOM 排障"实际不是 DCOM 问题:DCOM 连接正常(Connected in 4034ms,
  domain=WORKGROUP 也能认证),precheck 点位全 PASS

### 根因(三层证据链)
1. Utgard `ItemState.getValue()` 返回 `JIVariant`(javap 证实,不是解包后的 Java 数值)
2. `UdpRecordSender.numericValue` 只接受 `Number`,JIVariant 直接抛
   "OPC value is not numeric: [[123.0]]"([[x]] = JIVariant.toString(),内部是标量)
3. 旧 sendCycle 是"整轮编码后发送":一个点位编码异常 → 当轮全部点位不发 → 业务数据 0;
   心跳独立启动不受影响 → "有心跳无数据"

### 修复(d5702d9,129 测试全绿)
- `UtgardOpcDaClient.unwrapScalar()`:Utgard 边界统一解包 JIVariant
  (getObject() 解包;IJIUnsigned/JICurrency 特殊处理;JIException 保留原值由 sender 隔离)
- `UdpRecordSender.sendCycle()` 单点容错:坏点跳过 + recordsSkipped 计数 + 带 itemId 警告,
  其余有效记录照发
- 真 VT_ARRAY 不隐式降级取首元素(保持严格,spec 已记录决策)
- 测试:+5(unwrap 标量/货币/真数组;sender 跳过/坏点不阻塞)

### 验证
- ECU 部署新 jar 后:采集恢复,业务数据正常,中文 ItemID 也正常
