# 单点故障隔离与心跳来源校验规格（2026-11-11）

## 用户确认与范围

用户确认：“abc 三个点，某点的故障不应影响其他点的采集与转发。心跳来源确认。”
本规格替代此前“必须收齐配置全表才发送”的运行语义；保持配置字段、ItemID 原文、记录格式、时间戳、品质码和每包最多 48 条不变。

## 采集与转发

1. 每次实际同步读取明确标记开始和结束，结束时按配置顺序发送本次收到的点，不等待缺失点。
2. 本轮同一点多次回调只保留本轮最新结果；开始新轮清空缓存，结束后也清空。不补发旧轮值，不因晚到点补齐上一轮。
3. 数值、布尔及坏品质的数值继续沿既有编码路径；品质原样转发。无值、非数值、单点 HRESULT 失败仅跳过该点。
4. Utgard 每次读到的点均参与本轮，包括与上轮完全相同的状态；不采用变化抑制。
5. Utgard 批量结果转换抛运行时异常时，退回本轮逐点读取，隔离每点失败。正常路径仍使用一次批量读取；整次 RPC 的 JIException 沿连接故障路径处理，不把共同连接故障当作一个可绕过的点位错误。
6. 已绑定点恢复正常读取后自动参与下一轮；初始注册失败的 ItemID 不承诺自动重新注册，仍需修正配置/重启或另行设计单点注册策略。
7. 部分点缺失只做受限诊断，不因单点缺失重连整个连接。全连接无有效回调仍用既有连接看门狗。
8. 每次重绑使用新的回调身份，丢弃旧连接回调；周期开始清空缓存，避免跨周期/连接混入。
9. 完整快照停滞诊断改为完整点集长期缺失诊断，允许期间持续发送正常点；日志明确区分部分缺失与全无回调。

## 心跳来源

已确认应答源 IP/端口对应配置目标。接收端显式过滤源 IP/端口，不连接 UDP socket，保留既有发送错误行为。错误来源即使会话号匹配也不得更新状态。过滤不能被持续错误来源拖成无界等待，保留接收超时预算。

- [x] C 恢复自动参与下一轮；不重复旧值、不跨周期混包。
- [x] 相同 ItemState 连续两轮也转发；全空轮不发；大点表仍按 48 条拆包。
- [x] 旧连接的开始、点值、结束回调全部失效。
- [x] 本机 UDP 验证正确来源、错误端口、错误地址、超时及心跳状态。
- [x] 完整回归构建（175 个测试通过）。
